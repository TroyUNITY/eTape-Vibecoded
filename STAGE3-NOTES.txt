eTape — Stage 3: Filtered chart integration
============================================

What changed
------------
* Adds a Moomoo / Filtered source switch to the chart header. Moomoo remains
  the default and its existing K-line store and query path are unchanged.
* Filtered mode is available only on 1m and 5m. Switching to another
  timeframe automatically returns that chart to Moomoo.
* Filtered history loads the most recent five calendar days and reconstructs
  the selected timeframe using the Stage 2 filtered-bars engine.
* A two-second tail refresh updates the recent locally recorded TickStore
  prints. A separate once-per-minute refresh revisits the newest fully closed
  bars older than the Alpaca 16-minute Basic-plan cutoff, so delayed SIP trades
  can fill in after they become available.
* Filtered bars have their own UI store. They never overwrite Moomoo bars.
  If a provider reports an error, partial rows are merged without clearing
  previously known-good bars. A fully successful response replaces the queried
  interval, including removing bars that no longer qualify.
* The backend query is asynchronous, bounded to 14 days, and read-only. It
  does not submit, amend, cancel, or otherwise affect orders or execution.

Important data limitations
--------------------------
* Alpaca Basic historical SIP is delayed. The query client applies a 16-minute
  safety cutoff. The newest live tail therefore depends on TickStore recording
  the symbol's individual prints. If the symbol was not subscribed/recorded,
  those minutes may be empty until Alpaca releases the delayed history.
* TickStore cannot certify continuous capture. The status line intentionally
  labels local coverage as unproven and includes available reasons; an empty
  minute must not be interpreted as proof that no trades occurred.
* The existing 100-share price-forming rule and condition handling are applied
  by the Stage 2 filtered-bars engine. Smaller eligible reports may contribute
  volume without changing OHLC.
* The 20-second late-report rule cannot be applied to Alpaca historical reports
  because that API does not give us the provider receipt timestamp. It is
  flagged in the chart diagnostics. ADF venue filtering is also unavailable
  for local records because the TickStore archive does not retain exchange
  attribution.
* Engine-computed VWAP, EMA, SMA and MACD are suppressed in Filtered mode
  because they are calculated from the normal engine bar stream. Local Volume
  remains available; Volume Profile is unavailable in Filtered mode. Switching
  back to Moomoo restores the normal indicator and profile path.
* Level 2 visuals, Time & Sales, scanner, and all execution/order paths are
  unchanged. This does not claim exact parity with Warrior Trading / Day Trade
  Dash; feed coverage and condition mapping differ by provider.

Build and validation on Windows
-------------------------------
Requirements: Node.js 24 or newer, Go 1.26.5 or newer, and network access for
npm/go modules if the dependencies are not already cached.

1. In PowerShell, from this repository's root, run:

   Set-ExecutionPolicy -Scope Process Bypass
   .\build-filtered-windows.ps1

   The script runs npm ci and the UI build, copies the newly-built UI into
   engine/internal/webui/dist, and compiles the Windows executable with the
   embed_ui and tray build tags. The output is:

   dist\etape-windows-amd64.exe

   Do not launch dist\etape-custom.exe from an older package; it is not a
   Stage 3 build. This source handoff intentionally does not include a newly
   rebuilt executable.

2. For backend tests, from the engine directory run:

   go test ./cmd/etape ./internal/uihub ./internal/hist/filteredbars ./internal/hist/alpaca ./internal/hist/tradehistory ./internal/md ./internal/tickstore -count=1

3. For UI checks, from the ui directory run:

   npm.cmd ci
   npm.cmd run typecheck
   npm.cmd test

   The build script runs npm ci and npm run build again to ensure the embedded
   UI bundle is current.

Validation performed in the preparation environment
----------------------------------------------------
* gofmt completed for all modified Go files.
* TypeScript syntax transpilation passed for ChartPanel, ChartHeaderControls,
  their focused tests, FilteredBarStore, its tests, and the generated wire
  contract.
* A strict, no-emit TypeScript check passed for FilteredBarStore and its
  underlying store/wire types.
* Full Go tests could not be run here: the installed toolchain is Go 1.23.2,
  while this repository requires Go 1.26.5 (including a go.mod 'tool' directive).
* Full UI typecheck/tests/build could not be run here: the installed Node.js is
  v22.16.0, the UI package requires Node >=24, and ui/node_modules is absent.
* The existing embedded UI bundle and old executable were not rebuilt here.
  Run the included Windows build script before testing the new UI.
